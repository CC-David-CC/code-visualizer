## Ownership and execution design

```text
One ProjectAuthority
  authored math relations / typed symbols / solve configuration
  OR authored DC topology / typed parameters
                  |
          existing Freeze & Run
  retained input commit + attempt binding + edit protection
                  |
          host-owned preparation
  registered domain transformation, when required
                  |
       versioned mathematical problem
       validated units, kinds and scope
                  |
      derived symbolic / scaled numeric form
                  |
        registered linear equation backend
                  |
        existing publication / evidence admission
                  |
  solution values, residuals, diagnostics, typed resources
                  |
       original semantic IDs in every applicable view
```

Programming stays Python-native and unchanged. The mathematical backend is a
Python adapter using established libraries. Equations do not become ProgramModel
merely because Python solves them. Circuit topology belongs to its extension;
the shared compiler and solver contain no resistor, terminal or circuit cases.

Canonical equations are relations, independent of which symbol the user asks to
solve for. An explicit problem/request selects relations, known bindings, unknowns,
output units, scales and numerical policy by stable ID. Its accepted configuration
is part of the existing frozen input closure. The generic `ComputationRequest`
selects that request through typed, validated configuration; it does not carry an
opaque expression string or introduce another command bus.

SymPy expressions, coefficient arrays and generated mathematical domain contents
are disposable. They never enter the canonical project or its journal. A DC edit
changes the topology once; no rendered-view diff or reconciliation rebuilds it.
All derived identities use source IDs and semantic roles, with deterministic
ordering independent of display names, dictionary order or registry order.

## Commit sequence and stopping gates

These are implementation checkpoints inside P3, not new transition phases. Each
commit runs its focused tests plus the architecture/dependency gate. Resolve a
failed invariant before adding the next layer.

### 1. Establish versioning and compatibility before numerical work

Inventory every dimension-bearing native, journal, resource, evidence, terminal
and Protobuf record. Implement one bounded exact rational exponent representation:
normalized numerator/positive denominator, reduced factors, sorted unique basis
IDs and explicit size limits. Dimension arithmetic removes zero factors. Reject
irrational, nonfinite, malformed and out-of-bound exponents explicitly.
Legacy integer `n` decodes as `n/1`; there is no second dimension vector.

Version the changed dimension/unit contracts and their containing encodings where
required. Preserve v1 readers and writers for released artifacts. Do not globally
bump every CanonicalValue variant: an existing test deliberately rejects a tensor
merely relabeled as version 2. Unchanged scalar/tensor encodings and strict unknown
field/version rejection must retain their meanings.

Use the existing native-format migration path for authored changes, including
nested journal forward/inverse commands. Never rewrite historical resources,
evidence, retained commits, attempt bindings or their hashes on load. A historical
terminal must still validate against its own original encoding rather than being
round-tripped through whichever writer is newest.

Two source findings require an explicit design proof in this checkpoint:

* The workspace requires globally unique schema/concept/property/role IDs. A naive
  installation of overlapping v1/v2 schema definitions in one workspace is invalid.
  Settle the new math/unit schema contributions and migration together: retain the
  old assignment backend and published SI vocabulary, reuse their meaning, and
  provide a version-pinned algebra extension without duplicate schema identities.
  Record exact new public IDs/versions only after this coexistence fixture passes.
* P2 hashes `project_to_data(definition_state(project))`. Changing a writer can
  otherwise make an unchanged frozen variant look different after restart. Verify
  original retained bytes with the original versioned contract, then compare the
  migrated semantic definition through the same migration used by ordinary loading.
  Do not overwrite the old digest or skip a real semantic difference. Migration
  cannot turn a frozen variant into an unrun one; its first accepted semantic edit
  must still fork. Explicit execution under a changed implementation/input contract
  must not masquerade as a same-input replay.

**First proof:** an integer-dimension P2 project, journal, portable math plan,
resources and retained run survive migration/reopen with their historical bytes
intact; a rational-dimension authored project round-trips through native and wire
adapters, undo/redo and Freeze & Run. A stale marker still cannot admit an edit.
This gate precedes the general solver.

### 2. Prove unit algebra and the library adapter

Retain `UnitCatalog` as the derived authority over the selected canonical closure.
Use a bounded unit expression made from versioned unit-definition references and
exact rational powers. Arithmetic produces an immutable derived expression, not
a registry entry per operation. Named compound definitions explicitly state their
relationship to unit products; dimension equality alone never supplies it.

Resolve all unit, basis and compound-definition references through the existing
publication closure walker. Preserve immutable basis identity and separate public
ID/version ownership. Old SI definitions remain immutable; additions have explicit
owners and versions. Schemas and result descriptors must resolve the same closure.

Distinguish missing unit metadata from explicit dimensionless `one`. Carry
quantity kind as mathematical/domain meaning: linear quantity, affine point or
interval, with explicit cyclic/angular-frequency interpretation. Point minus point
produces an interval; point plus interval produces a point; point plus point and
multiplication of affine points reject. Offset conversion of a point must not be
silently applied to an interval. P3 may reject logarithmic and specialized frequency
operators explicitly rather than pretend they are ordinary unit arithmetic.

Use Pint behind an adapter generated solely from the selected canonical catalog,
with internal names derived from identities. Default names, prefixes, contexts or
equal dimensions cannot authorize an undeclared conversion. Validate authorization
before invoking library conversion. Test a same-dimension disconnected pair and
shadow names/versions, including compound conversions.

Add a tested optional scientific dependency group and worker environment. Pint,
SymPy, NumPy and SciPy are absent from the current development environment. Select
released versions by integration testing, then record exact versions, wheel hashes
and relevant numeric-library configuration. Missing optional packages must give a
capability diagnostic while the existing Python/math editor still opens and works.
Import numerical packages in worker/adapter paths, not at generic domain import or
GUI startup. Start with only libraries actually exercised by the P3 adapter.

**Gate:** P3-03/04/06/07/10 unit cases, bounded property tests, old unit/value/wire
tests and the unchanged historical foundation proof. Decide compound-unit encoding
here, before claiming an equation solution.

### 3. Add the mathematical problem and checked compiler

Extend the existing foundation concepts with the minimum typed symbol and problem
vocabulary. A symbol has identity, declared dimension, shape and quantity kind;
known values, requested unknowns and output units are explicit. Reuse mathematical
expression occurrences and relation identities. The same relation can have several
solve requests; selecting an unknown never converts equality into assignment.

The initial supported solve fragment is finite real scalar simultaneous linear
equalities, after substituting known bindings. Support addition, subtraction,
negation, multiplication/division when linearity is preserved and denominators
are valid known values. Rational unit powers are a type-system capability, not
a promise to solve nonlinear unknown powers. Type-check shapes, dimensions, kinds,
bindings and supported operators before numeric execution. Reject missing values,
contradictory known/unknown roles and unrecognized request fields with source IDs.

Construct derived SymPy nodes from an allowlist of canonical operators. Do not
parse author text with `sympify`, `parse_expr`, `eval`, `exec` or unchecked generated
functions. Extract a linear system only after semantic validation; no simplifier
may silently remove a domain restriction such as a possibly zero denominator.

Return an immutable internal checked problem with per-variable metadata,
per-equation dimensions, ordered identities and origins. Keep the portable boundary
within existing schema-validated terminal models and typed resources. Private
library objects stay inside preparation/backend execution.

**Gate:** P3-04/05/08/09/10 compiler cases; assignment evaluation is unchanged;
two unknown selections operate on the same canonical equation identities; malformed
or unsupported input does not reach a numerical solve.

### 4. Register the shared linear backend and portable evidence

Register a distinct exact-version backend for the equation problem representation.
`foundation.math.indexed_equations@1` remains callable with its original contract
and evidence encoding. Extend trusted worker composition and optional-dependency
capability checks; submit through the existing host service in GUI, CLI and tests.

After authorized conversion, form physical equations `A*x = b`. Each variable has
a positive finite scale `s[j]`; each equation has a positive finite residual scale
`r[i]` in that equation's units. Solve the dimensionless system
`A'[i,j] = A[i,j] * s[j] / r[i]`, `b'[i] = b[i] / r[i]`.
Keep the scale records and units, then restore solution values in requested units.
Never attach a single physical unit to a mixed voltage/current vector or matrix.

Use established rank-revealing numerical routines. State rank thresholds,
conditioning limits and residual tolerances in the validated request/evidence.
Distinguish inconsistent augmented rank, underdetermined rank, unsupported problem,
invalid input, ill-conditioning, numerical failure and cancellation. Redundant
consistent equations may yield a unique solution only when full column rank and
the stated residual test pass. Do not silently return a minimum-norm or least-squares
answer for an underdetermined/inconsistent problem. Nonlinear, ODE, DAE, complex
and spatial-field solving remain explicitly outside this backend's capability.

Emit solution observations and physical plus normalized residuals linked to the
original symbols/equations. Publish a typed solution/report resource containing
the checked numeric model, ordering, scales, solver identity and diagnostics for
inspection after process exit. Larger observations use resources; portable evidence
metadata remains within 2 MiB and uses existing chunk transport. Registered logical
types and their closure are mandatory. No automatic promotion into author state.

**Gate:** well-scaled/rescaled mixed-unit systems; inconsistent, singular and
underdetermined cases; cancellation and worker failure; portable plan/evidence
round-trip; result use after worker/host exit; old proof bytes unchanged. Instrument
the real host admission boundary to verify the durable freeze binding already exists.

### 5. Add DC topology and the non-electrical client

Ship an ordinary first-party DC domain extension: circuit, nets, component-owned
terminals, resistors, independent ideal voltage sources and an explicit reference
net. Terminals reference nets; component objects own the physical meaning. Require
valid endpoints, positive finite resistance and dimensionally valid parameters.
Report floating, contradictory and incomplete networks with component/net origins.

Derive equations from topology using one consistent current orientation:

* each resistor: `v(a) - v(b) - R*i = 0`;
* each ideal voltage source: `v(a) - v(b) - V = 0`, retaining its current unknown;
* each non-reference net: signed sum of incident currents is zero;
* reference potential is explicitly fixed to zero volts.

The domain transformation owns these equations and maps every generated symbol,
relation and occurrence to source nets/terminals/components. The general backend
only sees the resulting mathematical problem. Include a topology beyond the
divider and rename/reorder cases so the proof cannot be satisfied by its formula.

The electrical example uses 5 V and two 1,000 ohm resistors: midpoint 2.5 V,
branch currents 2.5 mA. A 1,000 ohm load parallel to the lower resistor gives
midpoint 5/3 V, upper current 10/3 mA, and lower/load currents 5/3 mA each.
Check independently calculated KCL and component residuals, including source sign.

The non-electrical example authors `F = k*x`, `F = 10 N`, `k = 200 N/m` and asks
for `x`; expect 0.05 m. It uses the same checked problem/backend, with no spring
case in the solver. Requesting `F` with `x = 50 mm` yields 10 N from the same
equation. Alternate unit inputs must preserve results through declared conversions.

For these small well-conditioned fixtures, use relative tolerance `1e-10` and
unit-specific absolute tolerances `1e-12 V`, `1e-12 A`, `1e-12 m`, `1e-10 N`.
Require normalized residual infinity norm at most `1e-10`; also check physical
residuals with declared units. These are initial acceptance targets to verify on
the locked environments, not measured accuracy or defaults for all future problems.

**Gate:** P3-01/02/03/05 through real host workers and retained typed results;
deterministic transformed structure/origins; canonical topology and relations do
not change merely because compilation or solving ran.

### 6. Complete authoring, Git comparison and release proofs

Expose quantity/unit selection and equation request fields through the existing
domain workbench and typed authority commands. Provide DC graph, parameter/table
and hierarchy views, plus equation/result inspection and shared source selection.
Layout is presentation. Invalid unaccepted text does not change model meaning.

Use real Qt actions and a real dirty temporary Git repository: author the divider,
Freeze & Run, inspect its result, then accept the load edit. Exactly one child
variant is created; further edits and undo/redo stay in it until run. Retain both
input commits and distinct attempts. Compare results by retained attempt/input and
stable semantic IDs, showing added/removed objects and units explicitly. Same local
revision numbers or matching labels must never attach old results to another branch.

Extend the existing retained-runs/evidence surfaces with comparison, using their
ordinary stores and background operations. Reopen both results after host restart,
branch switching and clean inactive worktree removal; verify resources and origins.
Repeat with persistent metadata failure and uncertain admission. Ready/unadmitted
bindings remain protected; recovery never silently executes. Preserve existing
checkpoint compatibility tests; the steady linear backend does not claim a new
checkpoint/resume capability.

Add both authored examples to normal verification without changing the 17 existing
examples or their expectations. Reuse `tools/prove_*` conventions for an isolated
physical proof that forbids ProgramModel lowering, solves through the shared host,
reopens portable results and resolves graph/table/form origins. Keep Git/resource
IO and numerical work outside Qt gesture handlers.

**Release gate:** every row in the acceptance map has an executed proof; all legacy
tests and new recovery/equation tests pass unchanged in the intended environments;
quality, wire generation, wheel, native and extracted-source checks pass. Produce
an environment lock, source-bound P3 receipt, raw logs, tolerances, limitations and
a separately named P3 archive/sidecar. Never overwrite P0/P1/P2 deliveries. Do not
claim Linux/macOS/native/symlink results unavailable on the executing machine.
